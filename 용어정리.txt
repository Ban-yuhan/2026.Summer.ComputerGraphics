[용어정리 - 배열과 포인터]

콘솔 : 텍스트로 데이터를 주고받는 입출력 창

참조: 원본변수에 접근하여 수정할 수 있도록 가져옴. 포인터를 사용할때 자주 사용함
복사: 원본변수의 값을 가져와 복사함. 복사한 값을 수정하기 때문에 원본 변수는 수정되지 않음

선언: 변수나 함수 등을 사용할 것이라고 컴파일러에 알림.
정의: 선언한 것의 내용을 실제로 구현하는 것
초기화: 선언과 동시에 값을 넣는 것.
함수: 특정 잡업을 수행하는 코드블록
식별자 : 무엇인가를 구별하기 위해 정해진 것. 변수나 함수의 이름.

전방선언 : 뒤에 이러한 이름의 함수나 구조체가 있다고 알려주는 것. C++은 단일 패스 컴파일방식이기 때문에 함수가 뒤에 있으면 main에 사용된 함수를 찾을 수 없기때문에 오류가 발생함.
함수의 선언 : 함수의 이름과 매개변수, 반환타입을 컴파일러에 알려줌.
함수의 정의 : 실제 함수가 수행할 내용.
함수의 호출: 함수를 부른다(실제로는 함수로 간다는 개념에 가까움)
전위 연산사: 값이 먼저 증가하고 대입(==복사)
후위 연산자: 값을 먼저 대입(==복사)하고 나서 값을 증가
데이터: 변수에 담기는 숫자 혹은 문자(열) 값
알고리즘 : 프로그램이 수행하는(내가 원하는 결과가 나오기까지의) 세부적인 모든 과정

변수: 데이터를 담을 수 있는 그릇
변수의 선언: 변수의 식별자(종류)와 이름을 컴파일러에 알림
변수의 초기화: 변수를 선언함과 동시에 값을 넣는 것
대입: 우항의 값을 복사하여 좌항에 넣음.
출력: print를 통해 데이터를 직접 확인할 수 있도록 출력
포인터: 변수의 주소값을 저장하는 변수
주소값: 메모리에서 데이터가 어디에 저장되어있는지 확인할 수 있는 값
포인터 연산: 포인터의 값을 증가시키는 연산. 변수의 크기만큼 주소값이 증가. +n을할 시 변수의 크기 * n개가 됨.
 
배열 : 연속으로 변수를 할당하여, 주소값을 통해 바로 인덱스로 접근 가능하도록 만들어진 변수.
배열의 선언 : 배열의 이름과 크기를 컴파일러에 알려줌.
배열의 초기화 : 배열의 각 index에 값을 넣는 것
배열의 복사: 배열은 =로 복사할 수 없기에 반복문으로 index를 하나씩 복사하거나, memcpy등을 통해 복사하여야함.
└memcpy(memoryCopy) : 데이터를 받을 배열 주소(도착지), 복사할 배열 주소(출발지), 배열의 크기 를 인수로하여 메모리주소값을 통해 배열의 값을 복사.
배열의 크기: 배열에 최대로 들어갈 수 있는 데이터의 개수

const : 상수. 컴파일 후 변하지 않는 값.

정적 : 코드가 컴파일되어 변경될 수 없는 상태
동적 : 프로그램이 실행되고 있는 상태
정적할당: 컴파일되기 전에 데이터를 할당
└ 컴파일러: 인간이 짠 코드를 컴퓨터 언어로 번역해 실행시킴
동적할당 : 프로그램이 컴파일된 후 주소값만을 사용해 실행되고 있는 중에 데이터를 할당
└ 런타임: 프로그램이 실행되고 있는 상태
└ malloc : 런타임에 필요한 만큼의 메모리 용량을 동적으로 할당받는 C언어 함수.
void포인터 : 데이터 타입 없이 주소값만 가지고 있는 포인터. 어떤 타입의 주소라도 담을 수 있음
sizeof : 식별자나 변수의 크기를 구함
포인터캐스팅 : 주소값의 타입을 변경하는 것


<배열과 포인터의 질문들>
· 코드를 작성 할 때, 참조자와 포인터 중 어느 쪽이 편리한가?

-> 참조자는 원본변수의 이름을 그대로 사용할 수 있기때문에 참조자가 편하다. 다만 도식화하기가 복잡함

· 그림을 가지고 설명 할 때 포인터와 참조자 중 어느 쪽이 이해가 쉬운가?

-> 포인터는 가르키고있는게 명확하게 표현되기에 도식화하기 편한다.

· 매개변수의 역할은 무엇인가?

-> 함수를 수행하는데 필요한 값을 외부에서 가져와 복사하여 함수 내에서 사용할 수 있게하는 변수.

· 아래항목을 각각 설명하여라.
 - Call By Value : 값을 복사하여 전달하기 때문에 원본수정이 불가능
 - Call By Refference : 참조자가 원본을 전달받기 때문에 원본수정이 가능

· 배열의 인덱스는 왜 0부터 시작할까?

-> 배열의 첫 인덱스주소가 배열의 주소가되므로, 0을더했을때 첫 번째인덱스가 나오도록 0부터 시작.

· 배열은 왜 일렬로 생성되는가

-> 배열의 주소를 알면 포인터연산을 통해 뒤쪽 index에 접근할 수 있도록 하기 위해

· 배열의 크기는 왜 상수로 지정하거나 초기화 해야하는가

-> 컴파일러가 배열의 크기를 알아야 메모리 할당이 가능하기 때문에, 배열의 크기는 컴파일 전에 확정되어야함. 따라서 반드시 상수로 지정하거나 초기화를 해 주어야 함.

· 배열은 왜 복사할 때 반복문을 이용해야하는가

-> 배열은 하나의 변수가 아닌 연속된 변수의 묶음이므로 단순 대입연산이 불가능

· memcpy()함수는 반복문을 이용한 복사와 어떤점이 다른가

-> 반복문은 index에 접근해 값을 하나씩 복사했다면, memcpy()는 도착지,출발지,메모리크기의 요소를 통해 출발지에서 지정한 크기만큼의 데이터를 통째로 도착지에 복사.


[용어정리 - 연결리스트]

구조체(struct) : 여러개의 데이터를 가진 변수
노드: 데이터 값과 다음 노드의 위치값을 갖는 데이터 묶음
리턴 : 함수를 수행하여 나온 값을 반환하여 데이터에 대입시킴
매개변수 : 함수 외부의 값을 함수를 수행하는데 사용하기위해 받아옴. 데이터의 복사이기에 매개변수를 수정해도 원본변수는 바뀌지 않음.
인수 : 함수를 실행하기위해 필수적으로 넣어야하는 값
NULL : 주소값이 할당되지 않아 아무런 데이터도 없는 상태.

순회 : 연결리스트의 모든 노드를 처음부터 끝까지 차례대로 거쳐가는 과정
연결리스트 : 노드끼리 포인터로 연결하여 배열처럼 연속되지 않고도 다음 노드에 접근 할 수 있는 자료구조.
메모리누수 : 메모리공간에 사용하지않는 데이터가 삭제되지않고 남아 쓸모없이 메모리가 사용되는 것

버그 : 프로그램 실행 중에 오류가 발생하여 원하지않는 값이 출력되거나 프로그램이 정상 작동하지 않는 것
└ 논리오류 : 알고리즘이 잘못되어 프로그램은 실행되지만 원치않는 결과가 출력되는 오류.
└ 런타임 오류 : 0으로 나누거나 메모리부족등으로 발생하는 오류로 프로그램이 비정상 종료됨.

포인터와 동적할당의 관계 : 런타임 중 동적할당시 데이터는 식별자 없이 주소값만을 갖기 떄문에, 포인터를 통해서만 접근이 가능함.

[그래프]

BFS : breadth first search. 너비 우선 탐색. 그래프에서 한 정점의 인접한 정점들을 먼저 탐색하고, 그 다음 깊이로 들어가서 탐색하는 방법.
DFS : depth first search. 깊이 우선 탐색. 그래프에서 한 정점의 인접한 정점들을 먼저 탐색하고, 그 다음 깊이로 들어가서 탐색하는 방법.

└ 캡쳐 : 람다 외부에 정의되어있는 변수나 상수를 람다 내부에서 사용. 참조/복사 가능

			외부의 변수가 a,b,c,d가 있다면
			[a, b] () {} ()  변수 a, b를 복사해서 람다 함수 내부에서 사용
			[&a, &b] () {} () 변수 a, b를 참조해서 람다 함수 내부에서 사용
			[a, &b] () {} () 변수 a은 복사, b는 참조해서 람다 함수 내부에서 사용
			[=] () {} () // 모든 외부 변수 result1, result2, result3, result4를 복사해서 람다 함수 내부에서 사용
			[&] () {} () // 모든 외부 변수 result1, result2, result3, result4 를 참조해서 람다 함수 내부에서 사용
			[&, result3] () {} () // 모든 외부 변수 (result1,2,4)은 참조로 사용하지만, result3만 복사로 사용
			[=, &result3] () {} () // 모든 외부 변수 (result1,2,4)은 복사로 사용하지만, result3만 참조로 사용

	지오메트리쉐이더 : 정점을 추가/삭제하여 지오메트리 형태 변형. 일반적으로 테셀레이션과 유사한 기능.

[GC]

- 세대구분 : 메모리를 나이에 따라 3가지 세대(Gen 0, Gen 1, Gen 2)분할하여 동작
	└ 0세대 : new로 막 생성된 객체들이 들어감. 매우자주, 빠르게 청소(Minor GC) (ex.받은메일함에 들어온 메일)
	└ 1세대 : 0세대에서 수행된GC에서 수거되지않고 남은(아직 사용중인) 객체들이 1세대로 넘어옴. (ex.중요문서함에 들어간 메일)
	└ 2세대 : 1세대에서 수행된 GC에서 수거되지않고 남은 객체들이 2세대로 넘어옴.(ex. 영구보관함에 저장한 메일)
