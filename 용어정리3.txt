◎ 1. C++ 언어 기초 & 메모리 매커니즘

[기본 문법 및 개념]

- 식별자 (Identifier): 변수, 함수, 클래스 등을 구별하기 위해 개발자가 부여한 이름.
- 데이터 (Data): 변수에 저장되는 숫자, 문자, 문자열 등의 값.
- 변수 (Variable): 데이터를 저장할 수 있는 메모리 공간의 이름.
- 선언 (Declaration): 변수나 함수의 이름과 타입을 컴파일러에 알림.
- 정의 (Definition): 선언된 변수/함수를 위한 실제 메모리 공간을 할당하거나 코드를 구현함.
- 초기화 (Initialization): 변수를 선언함과 동시에 최초의 값을 할당하는 것.
- 대입 (Assignment): 우항의 값을 복사하여 좌항에 저장하는 것.


□참조 (Reference) vs 복사 (Copy):
- 참조: 원본 변수의 메모리 주소에 별칭(Alias)을 붙여 원본을 직접 조작함.
- 복사: 원본의 값만 새로 할당된 메모리에 그대로 가져옴 (원본 수정 불가).


- 상수 (const): 컴파일 후 값을 변경할 수 없도록 고정하는 키워드.
- nullptr vs NULL:
- NULL: 정수 0으로 정의된 C 스타일 매크로. 정수형 함수 오버로딩 호출 시 버그를 유발할 수 있음.
- nullptr: C++11에서 도입된 포인터 전용 키워드. 타입 안전성(Type Safety)을 보장함.



[함수 및 연산자]

- 함수 (Function): 특정 작업을 수행하도록 묶어놓은 코드 블록.
- 전방 선언 (Forward Declaration): C++ 컴파일러가 위에서 아래로 코드를 읽을 때(단일 패스), 뒤에 정의될 구조체/함수의 존재를 미리 알리는 기법.
- 함수 호출 (Function Call): 해당 함수가 위치한 메모리 주소로 제어 흐름을 이동시킴.
- 매개변수 (Parameter): 외부에서 전달받은 값을 함수 내부로 가져오기 위한 변수.
- 인수 (Argument): 함수를 호출할 때 실제로 전달하는 값.
- 반환 (Return): 함수의 실행 결과를 호출한 위치로 전달하고 종료함.


- 연산자:
- 전위 연산자 (++x): 값을 먼저 1 증가시킨 뒤 연산에 참여함.
- 후위 연산자 (x++): 현재 값을 연산에 사용(복사)한 뒤 값을 1 증가시킴.
- sizeof 연산자: 변수나 데이터 타입이 메모리에서 차지하는 바이트(Byte) 크기를 반환함.
- 오버로딩 (Overloading): 이름은 같지만 매개변수 타입이나 개수가 다른 함수를 여러 개 정의하는 것.



[포인터와 메모리 할당]

- 주소값 (Memory Address): 메모리 내 각 바이트 위치를 나타내는 고유 번호.
- 포인터 (Pointer): 다른 변수의 메모리 주소값을 저장하는 변수.
- 포인터 연산: ptr + 1을 수행할 때 단순 1이 더해지는 것이 아니라 (포인터가 가리키는 타입의 크기 * 1) 바이트만큼 주소가 이동함.
- void 포인터 (void*): 데이터 타입 정보 없이 주소값만 가리키는 포인터. 모든 타입의 주소를 담을 수 있지만, 역참조를 위해선 형변환이 필요함.
- 포인터 캐스팅 (Pointer Casting): 포인터가 가리키는 메모리를 해석하는 타입을 강제로 변경하는 것.


- 정적 할당 vs 동적 할당:
- 정적 할당: 컴파일 타임에 메모리 크기가 결정됨 (스택 메모리 사용).
- 동적 할당: 런타임에 필요한 만큼 메모리를 할당함 (힙 메모리 사용, C에서는 malloc, C++에서는 new).
- malloc: 런타임에 지정한 바이트 크기만큼 힙 메모리를 할당하고 void*를 반환하는 C 함수.
- 메모리 누수 (Memory Leak): 동적 할당한 메모리를 해제(free/delete)하지 않아 힙 영역에 쓸모없이 남게 되는 현상.


Q. 참조자와 포인터 중 작성 시 편한 것과 그림 설명 시 쉬운 것은?
-> 작성 시에는 연산자(.)로 바로 접근 가능한 참조자가 편하지만, 도식화할 때는 가리키는 화살표 관계가 명확한 포인터가 이해하기 쉬움

Q. Call By Value vs Call By Reference
-> Call By Value: 값을 복사해 전달하므로 함수 내부에서 매개변수를 바꿔도 원본이 유지됨.
-> Call By Reference: 원본의 주소/참조를 전달하므로 함수 내부 변경이 원본에 직접 반영됨.

Q. 포인터를 매개변수로 전달받았을 때 원본 포인터의 주소값을 변경할 수 있는가?
-> 불가능합니다. 포인터 변수 자체도 값으로 전달(Call by Value)되기 때문에, 포인터가 가리키는 대상의 내용은 수정할 수 있지만 '원본 포인터 변수가 가리키는 주소' 자체를 바꾸려면 이중 포인터(T)나 포인터 참조자(T*&)를 전달해야 함

Q. 참조에 의한 호출의 구조적 이해에 이중 포인터가 쉬운 이유?
-> 참조는 역참조 동작을 문법 뒤로 숨기지만, 이중 포인터는 메모리 계층간 이동을 기호로 명시해 주므로 메모리 주소 관계를 파악하기 직관적


◎2. 자료구조 & 알고리즘

[배열 (Array)]

- 연속된 메모리 공간에 동일한 타입의 변수들을 일렬로 배치한 자료구조.
- memcpy: 반복문으로 인덱스에 접근하여 하나씩 복사하는 대신, CPU 메모리 블록 단위로 데이터를 통째로 고속 복사하는 함수.


Q. 인덱스가 0부터 시작하는 이유?
-> 배열명은 시작 주소를 의미하며, 인덱스는 '시작점으로부터 떨어진 거리(Offset)'를 뜻하므로 첫 번째 원소는 [시작주소 + (0 * 크기)]가 되기 때문입니다.

Q. 배열이 일렬로 생성되는 이유 및 크기 고정 이유?
-> 포인터 연산을 통해 인덱스 접근을 O(1)로 수행하기 위해 일렬로 할당되며, 컴파일 타임에 스택 메모리 배치 공간을 확정해야 하므로 상수로 지정해야 합니다.

[연결 리스트 (Linked List)]

- 데이터 필드와 다음 노드의 주소(포인터)를 가진 노드(Node)들을 연결한 자료구조.
- 구조체 (struct): 서로 다른 타입의 변수들을 하나로 묶은 사용자 정의 데이터 타입.
- 순회 (Traversal): 첫 노드부터 NULL을 만날 때까지 포인터를 타고 순차 접근하는 과정.


Q. 노드 중간 삽입/추가 시 어떻게 작동하는가?
-> 이전 노드의 next를 새 노드로 지칭하고, 새 노드의 next를 다음 노드로 가리키도록 포인터 재연결(Re-linking)을 수행합니다.

Q. 단일, 환형, 이중 연결 리스트 중 가장 많이 사용되는 것?
-> 이중 연결 리스트 (Doubly Linked List): 양방향 순회가 가능하고 삭제 시 이전 노드를 찾는 오버헤드가 없어 실무(STL std::list 등)에서 가장 널리 쓰입니다.

[이진 트리 & 힙 (Binary Tree & Heap)]

- 노드가 최대 2개의 자식 노드(Left, Right)를 가지는 트리 자료구조.
- 재귀 구조 (Recursion): 트리의 자식 노드 역시 하나의 작은 '서브트리' 형태를 띠므로 재귀 함수를 활용하면 로직이 매우 간결해집니다.
* 최소 힙 (Min Heap): 부모 노드의 값이 자식 노드보다 항상 작거나 같은 완전 이진 트리. 루트 노드가 항상 전체 최솟값을 유지합니다.
* 레드-블랙 트리 (Red-Black Tree): 노드에 색상(Red/Black) 조건을 부여하여 트리의 균형을 자가 조절(Self-Balancing)하는 이진 탐색 트리. 편향 현상을 막아 탐색/삽입/삭제 시간 복잡도를 항상 O(log N)으로 보장합니다. (STL std::map, std::set의 내부 구조)


Q. 이진 탐색 트리에 최솟값부터 순서대로 넣으면 발생하는 문제?
-> 데이터가 한쪽으로 쏠려 직선 형태의 편향 트리(Skewed Tree)가 되며, 탐색 성능이 O(log N)에서 배열과 동일한 O(N)으로 저하됩니다.

Q. 순회를 재귀 없이 구현할 때 스택(Stack)이 필요한 이유?
-> 재귀 호출 시에는 호출 스택(Call Stack)이 되돌아갈 부모 노드 주소를 기억해 주지만, 비재귀(반복문) 방식에서는 부모 노드로 되돌아갈 경로를 저장할 명시적 스택 자료구조가 필수적입니다.

[그래프 (Graph)]

- 정점(Vertex)과 간선(Edge)으로 이루어진 비선형 자료구조.
- BFS (너비 우선 탐색): 시작 정점에서 인접한 정점을 먼저 모두 방문하는 방식 (큐 자료구조 활용, 최단 경로 탐색에 유용).
- DFS (깊이 우선 탐색): 한 방향으로 갈 수 있는 끝까지 깊게 탐색한 후 돌아오는 방식 (스택 또는 재귀 활용).



[알고리즘 & 성능 분석]

- Big-O (점근식 표기법): 입력 데이터 수 N이 증가할 때 알고리즘의 최악 실행 시간(시간 복잡도) 또는 메모리 사용량(공간 복잡도)의 증가 추이를 나타내는 표기법.
- 사용 이유: 하드웨어 스펙과 무관하게 알고리즘 자체의 효율성을 객관적으로 평가하기 위함.


- 정렬이 필요한 이유: 데이터가 정렬되어 있으면 이진 탐색O(log N) 등 고속 탐색 알고리즘을 적용할 수 있어 검색 연산 비용이 대폭 감소합니다.
- 알고리즘 설계 과정: 문제 정의 -> 입출력 명세 -> 알고리즘 구상 및 수도코드 작성 -> 시간/공간 복잡도 분석 -> 코드 구현 및 예외 테스트.


◎ 3. C++ STL (Standard Template Library)

C++ 표준 라이브러리로, 표준 자료구조 컨테이너와 알고리즘, 이터레이터를 제공합니다.

- 이터레이터 (Iterator, 반복자): 컨테이너 내부 구조(배열, 연결리스트, 트리 등)에 관계없이 원소에 접근할 수 있도록 포인터를 추상화한 객체.
- 이터레이터 vs 포인터: 포인터는 실제 메모리 주소를 가리키는 C 언어 요소이고, 이터레이터는 내부 구성을 숨기고 ++, * 연산자 오버로딩을 통해 동일한 인터페이스를 제공하는 C++ 클래스 객체입니다.


- std::vector (동적 배열):
- 연속된 메모리 공간을 사용하며 동적으로 크기가 늘어나는 컨테이너.

Q. 데이터를 찾지 못했을 때 반환되는 값?
-> vec.end() (마지막 원소의 다음 위치를 가리키는 이터레이터)를 반환합니다.

Q. insert() 실행 시 연산 특징?
-> 지정한 위치 뒤의 데이터를 모두 한 칸씩 뒤로 이동시켜야 하므로 O(N)의 비용이 발생합니다.

Q. begin()과 end()의 차이점?
-> begin()은 첫 번째 데이터 위치를 가리키지만, end()는 마지막 데이터의 다음(Past-the-end) 빈 메모리를 가리킵니다. (반복문 종료 조건 판단을 단순화하기 위함)

Q. 비어있는지 판단하는 방법?
-> 논리적: vec.size() == 0, 호출 함수: vec.empty() (성능상 vec.empty() 권장).



◎ 4. 시스템, 운영체제 & 멀티스레딩

[메모리 및 실행 단위]

- 프로세스 (Process): OS로부터 독립된 메모리와 자원을 할당받아 실행 중인 프로그램.
- 스레드 (Thread): 프로세스 내에서 실행되는 실제 작업의 흐름 단위. 프로세스의 힙/데이터 영역을 공유하며 전용 스택만 보유함.
- 테스크 (Task): 특정 스레드에 귀속되지 않는 독립적인 '작업 단위(코드 + 데이터)'.
- 스레드 vs 테스크 구분법: 스레드는 작업을 수행하는 주체(Worker)이고, 테스크는 주체에 할당되는 할 일 목록(Work Unit)입니다.


- 컨텍스트 스위칭 (Context Switching): CPU가 실행 중인 스레드/프로세스를 변경할 때 현재 레지스터 및 상태 정보를 저장하고 새 상태를 복원하는 과정.
- 오버헤드 (Overhead): 시스템의 본래 목적 외에 제어, 관리, 동기화 등을 처리하기 위해 추가로 소모되는 간접적인 자원(시간/메모리).

[병렬 처리 & 잡 시스템]

- 잡 스케줄러 (Job Scheduler): 등록된 테스크들을 CPU 코어 수에 맞추어 스레드 풀(Thread Pool)의 워커 스레드들에 균등 분배하여 다중 코어 효율을 극대화하는 관리 시스템.
- 테스크 그래프 (Task Graph): 테스크 간의 실행 순서 및 의존성 관계(A 작업이 끝난 후 B 작업 실행 등)를 방향성 그래프(DAG) 구조로 표현한 설계.
- 크리티컬 섹션 (Critical Section, 임계 구역): 둘 이상의 스레드가 동시에 접근하면 데이터 오염이 발생하는 공유 자원 영역 및 이를 보호하기 위한 동기화 객체.

[비트 연산자 & 고급 C++ 문법]

- 마스크 (Bitmask): 비트 연산(&, |, ^)을 활용해 특정 비트 플래그를 켜거나 끄고, 원하는 조건 상태만 추출할 때 사용하는 비트 패턴 데이터.
- 람다 표현식 (Lambda): 이름 없는 익명 함수 객체. [캡처](매개변수) { 동작 } 형태로 선언함.
- 캡처 (Capture): 람다 외부 범위의 변수를 내부로 들여오는 방식. [=]는 값 복사, [&]는 참조 전달.



[가비지 컬렉터 (GC)]

- Mark-and-Sweep: 사용 중인 객체를 식별(Mark)한 뒤, 도달할 수 없는 객체를 메모리에서 해제(Sweep)하는 GC 방식.
- 세대별 GC (Generational GC): "최근 생성된 객체일수록 수명이 짧다"는 가설에 기반하여 3단계 세대로 나눔.
 ├ 0세대 (Gen 0): 신규 생성 객체. 빈번하고 빠르게 수거함 (Minor GC).
 ├1세대 (Gen 1): 0세대 GC에서 살아남은 객체. (버퍼 구역)
 └세대 (Gen 2): 1세대에서도 살아남은 장기 잔존 객체. (Full GC 대상, 수거 비용 큼)



 5. 객체지향 프로그래밍 (OOP) & 디자인 패턴

[객체지향 핵심 개념]

- 속성 (Attribute/Member Variable): 클래스 내부에서 객체의 상태 데이터를 표현하는 변수.
- 동작 (Method/Member Function): 객체가 수행하는 기능이나 로직.
- 이벤트 (Event): 시스템 내부나 사용자 입력에 의해 발생하는 상태 변화 사건.
- 상속 (Inheritance): 부모 클래스의 변수와 함수를 자식 클래스가 물려받아 재사용 및 확장하는 것.
- 다형성 (Polymorphic): 하나의 인터페이스를 통해 서로 다른 클래스의 객체가 각자만의 방식으로 동작하는 성질.
- 컴파일 타임 다형성: 오버로딩, 템플릿.
- 런타임 다형성: 가상 함수 기반 오버라이딩.


- 인터페이스 (Interface): 구현부 없이 순수 가상 함수만으로 규격을 정의하여 상속받은 자식 클래스가 반드시 구현하도록 강제하는 구조.
- 가상 함수 (virtual): 자식 클래스에서 재정의(Overriding)할 수 있도록 허용한 부모 클래스의 함수.
- 가상 함수 포인터 (vptr): 가상 함수를 가진 클래스의 인스턴스 내부에 컴파일러가 암묵적으로 추가하는 포인터.
- 가상 함수 테이블 (vtable): 해당 클래스의 가상 함수 메모리 주소들이 저장되어 있는 함수 포인터 배열.



[시스템 메커니즘 & 패턴]

- 콜백 (Callback) 구조 & 메시지:
- 메시지: 윈도우 클릭, 키 입력 등 시스템에서 발생하는 사건.
- 메시지를 콜백으로 처리하는 이유: 이벤트가 발생하는 시점을 예측할 수 없으므로, 사건 발생 시 OS가 미리 등록된 함수를 역으로 호출(Callback)해 주는 방식이 가장 효율적이기 때문입니다.


- 디자인 패턴: 자주 발생하는 클래스 설계 문제에 대해 검증된 표준 아키텍처 구조.
- 전략 패턴 (Strategy Pattern): 알고리즘/행동군을 캡슐화하여 런타임에 동적으로 교체할 수 있게 만드는 패턴.
- 관리자 패턴 (Manager Pattern): 특정 객체들(사운드, 씬, 텍스처 등)의 생명주기와 생성/소멸을 중앙에서 총괄 관리하는 패턴.
- 싱글톤 패턴 (Singleton Pattern): 인스턴스가 단 하나만 생성되도록 보장하고, 어디서든 전역적으로 접근 가능하게 만드는 패턴.

◎ 6. 컴퓨터 그래픽스 & Direct2D/Win32

[시스템 & 하드웨어]

- SDK (Software Development Kit): 소프트웨어 개발을 위해 제공되는 도구, 라이브러리, API 모음집.
- 라이브러리 (Library): 재사용이 가능하도록 미리 작성된 함수 및 클래스들의 집합.
- CPU vs GPU:
- CPU: 복잡한 제어 로직과 순차 연산에 특화된 컴퓨터의 핵심 처리 장치.
- GPU: 단순 대량 수치 연산을 동시에 수행하는 병렬 처리 전문 장치.


- APU (System on Chip): CPU와 GPU가 하나의 칩에 통합된 형태. (예: Apple M 시리즈)
- 하드웨어 최적화: GPU의 병렬 파이프라인 및 메모리 대역폭 한계를 고려하여 렌더링 병목을 최소화하는 작업.

[Direct2D & Win32 API]

- API: 애플리케이션 개발 시 운영체제나 시스템 자원을 제어할 수 있도록 제공하는 인터페이스.
- Factory (팩토리): Direct2D에서 렌더링 자원(타깃, 텍스트 서식, 지오메트리 등)을 생성해 주는 최상위 엔진 객체.
- HwndRenderTarget: Win32 윈도우 핸들(HWND)을 도화지 삼아 2D 그래픽을 직접 출력하는 Direct2D 전용 렌더링 타깃.
- HWND (Window Handle): 운영체제가 생성된 윈도우 창을 식별하기 위해 부여하는 정수 형태의 고유 식별자.



[렌더링 파이프라인 & 그래픽스 기법]

- 렌더링 파이프라인: 3D 가상 공간 데이터를 2D 모니터 화면의 픽셀로 변환하는 단계별 과정.
- 변환 순서: 로컬 스페이스 -> 월드 스페이스 -> 뷰 스페이스 -> 프로젝션(투영) -> 레스터라이즈.
- 레스터라이즈 (Rasterize): 정점 형태의 3D 벡터 데이터를 화면에 출력할 2D 픽셀로 변환하는 단계.

- 버텍스 (Vertex, 정점): 위치, 색상, UV, 법선 등의 정보를 포함하는 다각형의 꼭짓점 데이터.
- 버퍼 (Buffer): 데이터를 임시 저장하는 메모리 공간.
- 버텍스 버퍼: 정점 정보 배열을 저장하는 GPU 메모리.
- 인덱스 버퍼: 정점들의 연결 순서를 저장하여 버텍스 중복을 줄이는 버퍼.
- 깊이 버퍼 (Z-Buffer): 각 픽셀마다 카메라로부터의 거리를 기록하여 가림 처리를 연산하는 버퍼.
- 스텐실 버퍼 (Stencil Buffer): 픽셀 단위로 그리기 여부를 마스킹(Masking)하여 거울, 포털 효과 등을 표현하는 버퍼.


- 셰이더 (Shader): GPU 상에서 정점 위치나 픽셀 색상을 직접 계산하는 프로그램.
- 버텍스 셰이더: 정점 위치를 월드/뷰/프로젝션 좌표계로 변환.
- 픽셀 셰이더: 화면에 그려질 픽셀의 최종 색상과 조명을 계산.
- 테셀레이션 (Tessellation): GPU에서 정점을 동적으로 추가 분할하는 단계 (헐 셰이더 + 도메인 셰이더 이용).


- 컬링 (Culling) 최적화: 보이지 않는 물체를 연산 대상에서 제외함.
- 후면 컬링 (Back-face Culling): 카메라를 등지고 있는 물체의 뒷면을 제외.
- 절두체 컬링 (Frustum Culling): 카메라 시야 범위를 벗어난 물체를 제외.
- 오큘루전 컬링 (Occlusion Culling): 다른 불투명 물체에 완벽히 가려진 내측 물체를 제외.


- 공간 분할 자료구조:
- 쿼드트리 (QuadTree): 2D 공간을 재귀적으로 4개 영역으로 분할하여 컬링 및 충돌 검사 비용 감소.
- 옥타트리 (Octree): 3D 공간을 8개 영역으로 분할하는 3차원 확장 구조.
